# Progress — 22 October 2026

## Station Hub preview: Dashboard fixes and Task Assignment

Scope: the public `/logistics-preview/*` Station Hub pages only (hard-coded sample data, nothing saved). No migration, controller, model or live Logistics page was touched.

**Station Dashboard** (`resources/views/logistics/station/dashboard.blade.php`)

- **Parcels on hand** now counts only parcels at the station (awaiting sorting + ready for delivery + waiting for transfer = 61 in the preview). It used to add the 35 parcels out for delivery, which are with riders. The page subtitle states "out for delivery" separately.
- **Ready for delivery** now opens one place from both the attention list and the pipeline card: Task Assignment, Deliveries tab (`lgp.station.tasks?type=delivery`). Before, the two links went to different pages.
- **Today at this station** shows only counts for today (Received, Delivered). "Waiting for transfer" is current stock, not a daily count, so it moved to a note under the meters that links to Outgoing Transfers.

**Task Assignment** (new `resources/views/logistics/station/tasks.blade.php`; route `lgp.station.tasks` in `routes/logistics_preview.php` replaces the "coming next" placeholder)

- Spec sections 6A and 8. One page for every task that still needs a rider, with a Deliveries tab and a Pickups tab, search, barangay filter, select-all, and a sticky bar holding the required rider.
- Riders table shows availability, service barangays, pickup, delivery and workload meter (text beside the bar). Off-duty and full riders cannot be chosen; a rider who does not serve a selected barangay shows a warning but is allowed, because the assignment stays a manual Station Hub decision.
- Preview data: 3 unassigned pickups (same as Pickup Requests) and 31 delivery tasks (23 sorted today plus 8 carried over), so the delivery total agrees with the dashboard's Ready for delivery.
- Assigning changes page state only. Pickup assignments here and on Pickup Requests do not share state in the preview.

**Known gaps**

- Delivery Queue and Outgoing Transfers are still placeholders. The dashboard's failed-delivery "Review" link and the Out for delivery cards still open Delivery Queue.
- The capacity of 16 tasks per rider is a demo constant, not a business rule.
- The older `hub/assignments.blade.php` (reachable at `/logistics-preview/hub/station/assignments`, not in the sidebar) overlaps with Task Assignment and still uses its own 3-rider sample data. Decide whether to delete it once Delivery Queue exists.
- Static checks only: Alpine `x-data` syntax parsed with Node, Blade directive and tag balance counted. PHP was not available, so the Blade and route file were not compiled; no tests, builds or browser walkthrough were run. Owner testing pending at 375, 768, 1024 and 1440px and by keyboard.
