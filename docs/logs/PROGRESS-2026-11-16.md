# Progress - 16 November 2026

## Buyer app: the packed-item photo reaches the order detail screen

The Seller's **Photo of your packed item** card existed only on the web order page, so a Buyer on the phone could not see what the Seller packed before handover. The app reads `GET /api/v1/buyer/orders/{order}` and had no field or endpoint for that image.

- `app/Services/BuyerApiPresenter.php`: `orderDetail()` now sends `has_pickup_photo`, true when `pickup_photo_path` is filled, next to the existing `tracking` block.
- `app/Http/Controllers/Api/Buyer/BuyerOrderController.php`: new `pickupPhoto()` serving the private file with the same `private/pickup-photos/{order}/` prefix and existence checks as the web `OrderPickupPhotoController`, scoped to `buyer_id`, with `private, no-store` and `nosniff` headers.
- `routes/api.php`: `GET /orders/{order}/pickup-photo` inside the approved-buyer group.
- Docs: `docs/features/buyer/mobile-api/spec.md` records the flag and endpoint; `docs/features/buyer/order-status/spec.md` describes the card, the caption and that orders without a photo show no card.

Mobile side (separate repository): `ApiOrderDetail.hasPickupPhoto`, `BuyerApi.orderPickupPhotoUrl()` and a `_packedPhotoCard()` placed directly below **Shipment tracking**, drawn only when the flag is true so the two surfaces cannot disagree.

### Verified

- `php -l` on the presenter and the controller: no syntax errors.
- `php artisan route:list --path=api/v1/buyer/orders` lists `GET api/v1/buyer/orders/{order}/pickup-photo` among the buyer order routes.
- Not verified: no HTTP request was made and no image was opened. The app change is checked in its own repository; the owner should open a packed order on the phone after deploying this API and installing the new build.

### Gaps

- The photo needs the network: the cached offline order payload keeps `has_pickup_photo`, but the image itself cannot be served from the device, so offline the card shows *The packed-item photo could not be loaded.*
- The API deploy must land before the new app build, which otherwise simply hides the card.

## Placing an order in the Buyer app answered "Too Many Attempts"

- Added `PhilippinesLogisticsCompanySeeder`, an opt-in idempotent seeder that creates one approved Company-level Logistics account for each entry in the bundled PSGC province/area catalog. The seeder also creates one Province Hub and a Station Hub for every municipality/city in that province; no fictitious Sub Station level is seeded. Province Hub and Station Hub manager accounts are linked through `facility_staff`.
- Demo logins use `logistics.<province-slug>@vendo.com` and shared password `password123`. The seeder can be run explicitly in the presentation environment and is not registered in the default seeder.
- Added `logistics:demo-accounts-pdf [path]`; generated the credential PDF in Downloads, covering all 1,796 Company and facility-manager accounts with restrictive file permissions. The PDF was rendered and visually checked.
- Seeded the local `vendo` database: 82 Logistics Companies, 82 Province Hub managers, and 1,632 Station Hub managers (1,796 accounts), with 1,714 Province/Station Hub facilities. No migration was needed; one pickup-photo migration remains pending and is unrelated.
- The seeder hashes the shared password once per run to keep repeat seeding practical. It remains opt-in and is not registered in the default seeder.
