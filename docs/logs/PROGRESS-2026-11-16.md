# Progress — 16 November 2026

## Return pickup fee (reason-based payer, rider paid at pickup)

- **What changed.** A return now carries a fixed pickup fee, default ₱10.00, set by a super admin on **Admin → Finance → Delivery Fees** (`delivery_fee_settings.return_pickup_fee`) and snapshotted on the request when the Seller approves (`pickup_fee_cents`, `pickup_fee_payer`).
- **Who pays.** `damaged`, `wrong_item`, `missing_item` and `not_as_described` are charged to the Seller; `other` is deducted from the Buyer's recorded refund. `refund_cents` stays the gross amount and `buyerRefundCents()` is what the Buyer is shown and notified about.
- **Rider pay.** Only the successful pickup scan writes `order_return_pickup_earnings` (unique per return request), so approval, failed pickup and handover pay nothing and a retried scan cannot pay twice. The Rider earnings API returns these as `type = return_pickup` and the Station Hub cash ledger adds them to Rider earnings. The pickup response includes the fee and payer.
- **Files.** Migration `2026_11_16_100000_add_return_pickup_fee.php`; `DeliveryFeeSetting`, `OrderReturnRequest`, `OrderReturnService`, `ReturnTripService`, `Admin/DeliveryFeeController`, `Api/RiderEarningsController`, `Logistics/StationCashController`, `Seller/ReturnRequestController`, `Buyer/OrderController`; views `admin/delivery-fees/index`, `buyer/orders/return`, `buyer/orders/show`, `seller/returns/_row`.
- **Verified statically only.** `php -l` on the touched PHP and `view:cache`; no browser, device, or money-flow walkthrough was run. Owner verification and the migration are pending.
- **Known gaps.** The Seller-paid fee is recorded and shown, not debited from a Seller balance (no payout ledger exists). The Buyer-paid fee is deducted from the recorded refund; no cash is moved. A failed pickup needs a retry/reschedule rule. The Rider app needs a `return_pickup` label in its earnings list.

## Admin entry hardening, mobile-only Rider login, branded error pages

- **Hidden Admin path.** Added `config('app.admin_path')` from `ADMIN_PATH` (default `vendo-control`). Both `routes/auth.php` and `routes/web.php` now mount the Admin console there; the old `/admin` entry is intentionally unrouted and returns the branded 404. Logout and admin notification redirects use the configured path, with old stored `/admin/...` notification links migrated to the new prefix. Route names remain `admin.*`, so existing redirects and tests that use named routes keep working.
- **Admin account security.** Removed Admin self-registration and the unused Admin email-verification routes. Admin accounts are provisioned through Account Management. `AccountManagementController::table()` now requires `is_super_admin`, matching the other account-management actions. Regular Admin accounts remain valid; the change does not turn the console into a single-account login.
- **Mobile-only Rider/Driver login.** The logistics web login now rejects `courier` and `transport_driver` accounts with a mobile-app message and never redirects to the missing `logistics.courier.dashboard` route. The guest redirect for a legacy courier session points to the Rider app route instead.
- **Error pages.** Added `resources/views/errors/branded.blade.php`, `404.blade.php`, and `500.blade.php`: Vendo plum background, centered white-on-purple logo, HTTP code, back/sign-in links, and a support email on 500. Styles are inline so the page works without the Vite manifest; exception details are not rendered. The 500 page requires `APP_DEBUG=false`.
- **Operational note.** Set `ADMIN_PATH` to a private production value, then run `php artisan config:cache` and `php artisan route:cache`. Changing the environment alone will not move cached routes. `/admin` will remain a 404 by design.
- **Static checks only.** `php -l` passed on the touched PHP, `php artisan route:list` showed `admin.login` at `vendo-control/login` and no old `/admin` routes, and `view:cache` passed. No browser, role-by-role, or device walkthrough was run; owner verification is pending, especially the hidden-path login and the rendered error pages.
