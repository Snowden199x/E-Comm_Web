# Progress log: 8 November 2026

## Buyer UI/UX pass: Dashboard and shared header

- **Header menus.** The account menu opened behind the category menu because `.vb-header` created its own stacking context and the category menu is a later sibling. `.vb-header` is now `z-30` and the category menu `z-20`. Moving up from the category strip closes the category menu, and the category, account and notification menus close each other through one `vb-menu` event. The account menu also opens on hover (desktop) and keeps a click/tap fallback. It shows the buyer's email instead of "Buyer account", with icons and shorter labels (Orders, Vouchers, Complaints, Favorites, Account, Settings, Log out).
- **Favorites page.** New route `buyer.favorites` (`GET /buyer/favorites`) and `PersonalizationController@favorites`. Renders saved products with the shared product card, with search, sort, "Clear all" (inline confirm) and Undo. The slide-over panel is removed; the old `open-favorites` event now navigates to the page. The existing JSON `saved-items.*` routes are unchanged.
- **Banner notifications.** New `buyer/partials/banner.blade.php` (Alpine store `banner`, pastel success/error/warning/info, optional action, pause-on-hover progress bar, reduced-motion fallback). `$store.ui.say()` still works and maps to it. Add to cart now opens a banner (the `#buyer-toast` element is kept as the ajax target). A new notification opens an info banner and rings the bell; `NotificationController@recent` returns a `latest` object for it.
- **Icon animation.** Hover animations on search, messages, cart, bell, favorites, category grid, back-to-top and arrows. Heart beats when a favorite is added, cart bumps when an item is added, bell rings on a new notification. All finite; off for reduced motion and Settings > Reduce animations.
- **Dashboard.** Pastel single-color hero (was four dark colors). Benefits strip removed (repeated in the footer). Shortcuts are now Track orders, View cart (with count) and View favorites (with count), each with an arrow. Product cards add directly (`toProduct` no longer forced); the card labels now say what happens ("Add to cart", "Choose options"). Category circles now use the photos in `public/images/categories` (the old path `images/buyer/categories` does not exist) with a tinted initial as the fallback. Empty states for categories and products.
- **Shared styles.** `layout.css` gained `.vb-btn` (primary, outline, danger), `.vb-field`, `.vb-loading` spinner, banner and icon keyframes. Product card and quick-add use them; labels are sentence case.
- **Loading.** Normal form submits (buyer layout) lock the submit button and show a spinner. Add to cart shows a spinner. Heart buttons lock while saving. Notification polling skips hidden tabs.
- **Errors say the fix.** Cart messages ("Only 2 left in stock. Lower the quantity and try again."), favorites limit ("Favorites are full (60 max). Remove one to add another."), offline and expired-session messages in the favorites requests.
- **Files.** `routes/web.php`, `PersonalizationController`, `NotificationController`, `CartController`, `DashboardController`; views `components/buyer/layout`, `components/buyer/empty-state` (heart icon), `buyer/dashboard`, `buyer/favorites` (new), `buyer/partials/banner` (new), `favorites-panel`, `product-card`, `quick-add`; `resources/css/buyer/layout.css`.
- No migration. No new dependency. No new Vite input.

**Verified:** `php -l` on the five PHP files; Blade compiled and the output linted for the changed views; inline scripts pass `node --check`; the favorites page logic and the banner/favorites stores were exercised in Node with stubs. **Not verified:** no browser walkthrough, no `npm run build`, no database. Check hover/click on the account menu over the open category menu, add and remove a favorite (Undo), Clear all, add to cart (success and out of stock), and a new notification, at phone, tablet and desktop widths.

**Known gaps**

- Other Buyer pages (Products, Cart, Checkout, Orders, Account) still have their own inline success messages and old spacing. They are next, one page at a time.
- Notification polling is still every 3 seconds.
- The notification icon palette still has a blue "message" tone.

## Buyer order detail: cancel dialog

- **Dropdown.** The native "Reason" select is replaced by a custom dropdown that opens in the flow of the dialog, so it is never clipped on a phone. It has a check on the chosen row, arrow-key and Escape support (Escape closes the list first, then the dialog), and focus moves to the next control after a pick.
- **Dialog.** Shows the order number and total, and says stock returns to the seller and the cancel can't be undone. "Cancel order" stays disabled until a reason is chosen (and a 3+ character note for "Other"), with a line saying what is missing. "Other" shows a character counter. Buttons use the shared `.vb-btn` styles; submit shows the spinner from the buyer layout. Focus returns to the "Cancel order" button on close.
- **Errors.** Server errors for `reason` and `reason_details` show under the field with the fix, inside the reopened dialog, instead of a duplicate bar at the top of the page.
- **File.** `resources/views/buyer/orders/show.blade.php` only. Field names, route and validation are unchanged.

**Verified:** Blade compiles; the `x-data` block parses and its `ready` rule was exercised in Node; tag balance. **Not verified:** browser. Check open, pick each reason, "Other" with and without a note, Escape, a phone width, and submitting with the reason removed.

**Known gap:** a 409 ("This order has changed") from the server still shows the framework error page.

## Dim layer not full screen, and Account page rework

- **Dim layer bug.** The page-enter (`.vb-enter`) and header-drop animations used `fill-mode: both`. A finished animation that keeps its last frame still counts as a transform, so it became the containing block of every `position: fixed` child: dialogs dimmed only the page column, not the header or side margins. Both now use `backwards`, which fixes every Buyer dialog at once (cancel order, checkout address and others). The cancel dialog is also teleported to `<body>` (`x-teleport`).
- **Account page (`buyer/account.blade.php`) rebuilt.** Routes, field names and the controller contract are unchanged.
  - Messages: success and failure open as banners; every field shows its error with the fix and a rose border.
  - Photo and banner: both menus were clipped by the card's `overflow-hidden`; fixed. Uploads are checked in the browser (image type, 2 MB photo, 4 MB banner) with a banner explaining the fix, and show a spinner over the image while uploading. Menu items are "Upload photo/banner" and "Remove photo/banner".
  - Profile form: optional fields are marked "Optional", street is marked required (the server already required it), an "Unsaved changes" hint, and a sticky Save bar.
  - Password: show/hide, live strength bar, live "at least 8 characters" and "passwords match" checks, and the button stays disabled until the form can pass.
  - Appearance: shorter copy; reset asks inline ("Reset all" / "Keep settings") instead of "Click again".
  - Delivery: the select became radio cards (same field name and values, "Lowest fee" is the empty value); empty state when no provider serves the address.
  - Favorites tab (was "Saved items"): count, six thumbnails, link to the Favorites page, inline-confirm Clear all (Undo banner). The full list is no longer duplicated here.
  - Labels cut and made consistent: Profile, Password, Appearance, Delivery, Notifications, Favorites, Privacy and terms.
- **`AccountController`:** validation messages now say the fix (shared `MESSAGES` constant, password messages, wrong-password message). Success messages shortened ("Profile saved", "Password updated").
- **Files.** `resources/css/buyer/layout.css`, `resources/views/buyer/orders/show.blade.php`, `resources/views/buyer/account.blade.php`, `app/Http/Controllers/Buyer/AccountController.php`.

**Verified:** `php -l`; Blade compiled; all `x-data` blocks parse. **Not verified:** browser. Check the cancel dialog dims header and side margins; upload a photo, a 5 MB image and a PDF; save the profile with an empty street; change password with a wrong current password; pick a delivery provider; clear favorites and Undo.

**Known gaps:** photo/banner uploads still reload the page (no in-place preview); the map pin component is unchanged; the Privacy tab's policy list (`x-account-policies`) keeps its own styling.

## Account: photo and banner cropper, per-field password eye

- **Cropper.** Choosing a profile photo or banner now opens a crop dialog instead of uploading straight away. Drag to reposition; zoom 1x to 4x with the slider, the +/- buttons, mouse wheel, pinch, or the + and - keys; arrow keys move (Shift moves faster); "Reset position" re-centers. The image always covers the frame. The photo uses a circle mask and saves 512x512; the banner uses a thirds grid, a 4:1 frame, and saves 1600x400. "Save photo/banner" draws the visible part to a canvas as a JPEG (quality 0.9), puts it in the same file input and submits the same form, so routes, field names and server validation are unchanged. Cancel or Esc clears the choice. The dialog is teleported to `<body>`.
- **Limits.** The browser accepts source images up to 15 MB (they are shrunk before upload, so the server's 2 MB and 4 MB limits are no longer hit in practice). Non-images and files the browser cannot decode (for example HEIC) show an error banner with the fix.
- **Password.** The "Show passwords" toggle is replaced by an eye button inside each of the three fields, so each shows or hides on its own.
- **File.** `resources/views/buyer/account.blade.php` only.

**Verified:** Blade compiles; all `x-data` blocks parse; the crop methods were run in Node (clamping, zoom limits, zoom around center, pinch, drag, keyboard, narrow phone frame, images smaller than the frame, cancel). **Not verified:** a real browser (canvas export, `DataTransfer`, touch). Check on desktop and a phone: pick a large photo, drag, zoom, save; pick a PDF; cancel; and each password eye.

**Known gap:** re-adjusting an already uploaded photo needs the original, so "Edit banner" and the photo menu still start from a new file.
