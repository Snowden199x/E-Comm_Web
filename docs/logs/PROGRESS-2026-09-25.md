# Progress — 25 September 2026

Seller Delivered Orders, feedback management, reports, account management and notification pages are now backed by seller-scoped data and actions. Reports offer Today, This Week, This Month and This Year, with a modal preview and PDF download. The account page stores a shop profile and banner. Delivered Orders uses actual delivery states; feedback connects buyer reviews, seller replies and admin moderation. Product creation and inventory now include product attributes, selectable variants, a main image and gallery, and stock filters.

Buyer-facing work includes a public seller profile, order-linked buyer–seller chat, and buyer notifications. The seller dashboard header and messages area were also updated to use the same account and notification behavior as the other web roles.

Buyer–seller chat shows the first product photo in shared order cards, both on initial page load and when a new order reference arrives. Existing authorization restricts order references to the buyer and seller in that conversation.

Open buyer, seller and admin message threads update without a page reload. The buyer and seller chat lists also update while their Messages pages remain open. Admin support conversation lists refresh in the same way. These screens use short, visibility-aware requests with the current Laravel server; a broadcast/WebSocket service is not configured. Delivery is normally visible within one to two seconds while the tab is active.

Admin notifications show platform records only, so matching admin and customer IDs cannot mix inboxes. New buyer and seller registrations and incoming support messages create admin notifications. The admin bell shows an unread count and refreshes while the page is open. The inbox can filter unread items and mark one or all as read. Notification links stay under admin routes.

The seller dashboard and bell show roughly three recent notifications before scrolling to more items; both refresh while the page stays open. The notification panel links to the full inbox, and Inventory Alerts links to filtered product inventory. Seller notification controls play a short sound after browser audio has been enabled by interaction; newly observed notifications also play the sound.

The Admin complaints preview now stays within the viewport and wraps long descriptions. The Product review reports link has been removed from Complaints and Disputes. Existing moderation routes remain available to Seller Feedback reports. Complaint order items open a product detail dialog with the product gallery, description, attributes, purchased variant, quantity and price. Buyer and seller account reports accept up to five photos or PDFs (5 MB each). Evidence is stored privately and served to authenticated Admins from the complaint record. The Admin bell now opens a recent-notification panel with a View all link, matching the Buyer and Seller flow.

Vendo Support on Seller Messages now starts with the same three reasons as Buyer Support and sends an automatic acknowledgement. A closed support conversation can be followed by a new one. Buyer–Seller chat separates messages by order: sharing an order opens that order's thread, and the server rejects references to a different order in the current thread. The first buyer message receives a clearly marked Vendo acknowledgement. Shared order cards now show the product photo, title, item count, amount and current status. The chat layout has been adjusted for desktop and mobile reading.

When an order with an existing buyer–seller conversation changes status, Vendo adds a templated order update in that order's chat. The update includes the order card and current status; it does not post to other orders or create an AI reply.

The nullable sender migration for marketplace system messages was applied to the local database. It must also run in each deployed environment. The frontend build, Blade compilation, route listing and PHP syntax checks passed. Manual browser verification remains with the project team.

Warning and policy-update notifications now open an in-page detail dialog for Buyer and Seller; Admin notifications without a destination also open a detail dialog. The policy dialog includes the current policy text. Seller header account menu remains clickable without the chevron icon. Buyer, Seller and Admin can permanently delete their own support messages, and Buyer and Seller can delete their own marketplace messages. Each deletion requires a confirmation dialog, removes stored attachments, and disappears from active chat views.

Buyer, Seller and Admin order-related screens now check for changed server data every three seconds while the tab is active. Order lists, dashboards, inventory, feedback, registrations, complaints and notifications refresh when their data changes; a visible draft or dialog is preserved and a refresh prompt appears instead. Cart, checkout and product detail pages prompt for refresh so choices and address text are not lost. Seller Order Management now refreshes its list and open detail panel every three seconds. Messaging continues to poll every second. This is short-interval polling, not WebSocket broadcasting.

Checkout now rejects a stale cart snapshot if price, stock, options or cart contents changed after the buyer opened the page; the buyer can review the latest total before placing an order. Checkout creates an Admin new-order notification alongside the Seller notification. Shipment tracking edits notify the Buyer. Delete-message controls on outgoing Buyer, Seller and Admin chat bubbles were given visible high-contrast styling.
