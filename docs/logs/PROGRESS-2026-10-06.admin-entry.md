# Progress — 6 October 2026

## Admin: document viewer popup, ID preview fix, and Seller Compliance UI redesign

Presentation only. No controller, route, model, migration, or schema change. The Admin shell (sidebar, top bar, bell) is unchanged. Backend items found along the way are in [Admin backend needs](../design/2026-10-06-admin-backend-needs.md).

### User Management and Registrations: ID preview and file popups

- **Root cause of "Preview unavailable":** Buyer, Seller, and Logistics uploads accept `jpg, jpeg, png, pdf`, but the ID preview was an `<img>`. A browser cannot draw a PDF in `<img>`, so every PDF ID failed. The old fallback also gave no reason and told the admin to open the file in a new tab.
- **Shared popup:** one document viewer is rendered once by `components/admin/layout.blade.php` (`admin/partials/document-viewer.blade.php`, logic in `resources/js/admin/document-viewer.js`). Any Admin screen opens it with `$dispatch('open-document', { url, title, subtitle, filename, kind })`. Registrations details, User Management profile, and the Dashboard "Recent Registrations" dialog all use it.
- **No new tabs:** the ID file chips (`valid_id.*`, `second_id.*`) and the business permit link were `target="_blank"` links. They are now buttons that open the popup. `id-lightbox.blade.php` is no longer included anywhere and can be deleted.
- **Behavior:** the file is fetched with the admin session from the existing `admin.verification-documents.show` route and shown from an in-memory blob URL, which is revoked when the popup closes. Images get zoom (buttons, `+`, `-`, `0`); PDFs use the browser's PDF viewer. Specific messages for 404 (file missing from private storage), 403, expired session (HTML login response), 5xx, network failure, unsupported type, and a damaged image, with "Try again" where a retry can help. Esc closes only the popup (capture-phase handler), Tab is trapped inside, and focus returns to the trigger.
- **Thumbnail:** an image ID shows as before; a PDF ID shows a document tile; a thumbnail that fails to load shows "Preview couldn't load / Click to see why". The ID partial still takes `$user`, `$details`, `$ext`.
- **Files:** `resources/js/admin/document-viewer.js` (new, imported from `resources/js/admin/layout.js`), `resources/views/admin/partials/document-viewer.blade.php` (new), `resources/views/components/admin/layout.blade.php` (one `@include`), `resources/views/admin/registrations/partials/{id-preview,applicant-details}.blade.php`, `resources/views/admin/user-management/partials/profile-modal.blade.php`.
- **Fix during handoff:** the first version used `@error=` on the image tag. Blade treats `@error(...)` as its validation directive and the page failed with a `ParseError` ("expecting endif"). It now uses `x-on:error` / `x-on:load`. Do not write `@error`, `@json`, `@class`, `@style`, `@checked`, `@selected`, `@disabled`, `@required`, `@session`, or `@auth` as Alpine shorthand in Blade; use `x-on:` or `@@`.

### Seller Compliance redesign (Overview, Products for Review, Warnings, Violations, Suspended Sellers)

- **Pattern:** matches the 4 October User Management list. Page header, section tabs, four summary cards, search and filters, one rounded table card, and a footer with "Showing 1–8 of N entries" and boxed pagination. Shared markup lives in `partials/{tabs,stat-cards,table-shell,empty-state,pagination}.blade.php`; the five tables and four dialogs were rewritten.
- **In-place refresh:** search, category and date filters, and paging fetch the existing `*-table` partial routes and swap `#sc-region` with a loading bar, a request-cancel guard, debounced search, and `history.replaceState`. Dialog state is closed on each swap. Behavior is in `resources/js/admin/seller-compliance.js` (`scTable`). Pagination previously used Laravel links that pointed at the bare partial route after an AJAX refresh; page buttons now use `data-page`.
- **Icons:** new stroke icon set in `components/admin/icon.blade.php` (`<x-admin.icon name="…">`) replaces the old PNG/SVG file icons and the text glyphs in dialogs. Used for tabs, cards, status pills, filters, and dialogs.
- **Motion:** tab highlight slides between tabs and the page cross-fades using cross-document view transitions where the browser supports them; cards rise in sequence; rows settle in after each refresh; score bars grow; the empty-state badge floats; result dialogs pop and draw their check, cross, or exclamation; menus and dialogs fade and scale. Everything is turned off for `prefers-reduced-motion`. Styles in `resources/css/admin/seller-compliance.css` (`sc-` prefix), registered in `vite.config.js`.
- **Empty states:** every table has its own empty message and a separate "no results" message with "Clear filters" when a search or filter is active.
- **Cards:** the cards on each tab now link to the matching tab. The label "Sellers with Violence" was corrected to "Sellers with Violations".
- **Overview:** seller avatar initial, category badges, color-coded compliance score bar (80+ green, 50–79 amber, below 50 red), warning and violation count chips, Compliant/Suspended pill, and a link to that seller in User Management (`admin.user-management.index?search=<email>`).
- **Products for Review:** product thumbnail with a no-photo placeholder, seller and shop, category badge, submitted date with relative time. The review dialog has a photo gallery (arrows, thumbnails, counter, Left/Right keys), sections for description, product information, specifications, variations, and video, and a sticky action bar (Reject, Issue warning, Approve). Reject and warn dialogs use radio cards, a 500-character counter, and a busy state. Field names (`reason`, `details`), reason lists, and routes are unchanged; `data-draft-key` is kept so unfinished input still survives a same-tab reload.
- **Suspended Sellers:** reason, "Since" date, live countdown (timer is cleaned up when the region is swapped; the old one leaked), or a Permanent chip. **Activate now asks for confirmation** in a dialog before posting to `admin.user-management.activate`, then shows a "Suspension lifted" result dialog from `session('confirmation')`.
- **Result dialog copy:** states only what the controller does. Approve, reject, and warn each create a Seller notification; reject also records a violation. A warning count divisible by 3 also records an automatic violation, and 3, 6, and 9 violations suspend for 7 days, 30 days, and permanently (`SellerComplianceController::escalateSuspension`).
- **Search scope (unchanged):** Overview and Suspended search seller name or email; Products searches product name or seller name; Warnings and Violations search seller name or email. Placeholders now say exactly that.

### Known gaps

- Backend items are listed in [Admin backend needs](../design/2026-10-06-admin-backend-needs.md): privatizing legacy documents where needed, viewer audit, compliance-score queries, stat definitions, live updates on three tabs, and suspension rules shown in the UI.
- The viewer cannot show files that are missing from private storage. It reports them as "File not found"; fixing the file is an operations task (`verification:privatize` or re-upload).
- Android and some mobile browsers do not render PDFs inside an iframe. The viewer shows a blank frame there; desktop Admin is the supported target.
- Cross-document view transitions need a supporting browser (current Chromium and Safari); others navigate normally.
- No tests, build, or browser walkthrough were run. Alpine/JavaScript syntax was checked with `node --check` and Blade directives were checked for balance only; PHP was not run, so compiled views are unverified. Owner verification is pending: popup open/close and Esc stacking over the profile dialog, PDF and image IDs, the in-place refresh with a dialog open, the Activate confirmation, and the view-transition tab slide. Run the normal Vite process and `php artisan view:clear` first.
