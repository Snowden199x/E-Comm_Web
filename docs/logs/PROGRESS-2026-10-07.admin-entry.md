# Progress — 7 October 2026

## Admin: shell, Dashboard, Seller Compliance popup, stat cards, and Complaints and Disputes redesign

Presentation only. No controller, route, model, migration, or schema change. Backend items found along the way are in the [7 October frontend pull review](../design/2026-10-07-pulled-frontend-review.md).

### Admin shell: sidebar, top bar, loading screen

- **Sidebar:** links are grouped (Dashboard; Review; Business; System) with 40px rows, a 72px brand bar, and the whole menu centered vertically between the logo and Logout (`my-auto` on the list, so on a short screen it collapses and scrolls). The logo is sized by height so it is centered in its bar and no longer touches the first link. The label is now `Complaints & Disputes` and fits on one line next to its count badge; every link has a `title` tooltip (the collapsed rail relies on it). The sidebar is flat plum (no gradient) with a gold marker on the active item.
- **Count badges:** Registrations (pending sellers, buyers, logistics centers), Seller Compliance (products with status `for_review`), and Complaints and Disputes (status `open`). Collapsed rail shows a gold dot instead. The three counts are read inside `sidebar.blade.php`; moving them to a view composer is listed in the backend needs.
- **Top bar:** 72px so its border lines up with the brand bar. Shows the page `$title` next to the menu toggle when a page passes one.
- **Loading screen:** a flat plum screen with the logo, "Preparing your workspace", and a gold progress bar appears on every full page load (about 0.6 s minimum). It paints from an inline style before any stylesheet loads, is removed by `motion.js` on `load`, and has an 8-second safety timer in the layout so a failed script cannot leave it on screen. In-app navigation (`x-target` links) shows a thin gold progress bar and dims the page, then replays a short entrance animation. Everything is off for `prefers-reduced-motion`.
- **Files:** `resources/css/admin/motion.css` (`vd-` prefix), `resources/js/admin/motion.js` (imported by `layout.js`), `resources/views/components/admin/layout.blade.php`, `resources/views/admin/partials/sidebar.blade.php`.

### Dashboard

- **Needs your attention:** one card with four counts, each linking to its queue: registrations to review, products awaiting review, open complaints, suspended sellers. A zero shows "All clear" text instead of a number. The counts are read in `dashboard.blade.php` (`$attention`, used if the controller passes it).
- **Stat cards:** total orders, sales, users, sellers, with a week-over-week change from the six weekly chart buckets already supplied. The current week is partial, so the change compares this week so far with last week.
- **Sales overview:** flat bar chart with a Sales | Orders toggle (`resources/js/admin/dashboard.js`, Chart.js from the CDN as before). Empty state when there are no orders in six weeks. The sales summary gained completed and returned/refunded rate bars.
- **Rest of the page:** time-of-day greeting with quick actions, recent registrations (approve, reject, and details dialogs unchanged), recent complaints and disputes linking to each case, notifications, pending registrations by type, and a flat announcement card. Each list has an empty state. No gradients.
- **Files:** `resources/views/admin/dashboard.blade.php`, `resources/js/admin/dashboard.js`.

### Seller Compliance

- **Seller popup:** clicking a row on the Overview table opens a popup with the seller's products (photo, name, category, price, stock, status, filterable by status), and a tab for warnings and violations with their reason, details, date, and product. Empty states for no products and for a clean record. A link goes to the seller in User Management.
- **How the data is read:** the popup reads up to 48 products and 10 warnings and 10 violations per seller on the page, directly in `sellers-table.blade.php` (about five queries per row). This keeps the controller untouched; the lean version is in the backend needs. Open state is `sellerId` in `scTable` (`resources/js/admin/seller-compliance.js`).
- **Products for Review count:** the tab bar shows the number of products waiting for review beside "Products for Review" (gold on the active tab, amber otherwise, `99+` cap) when above zero.
- **Files:** `resources/views/admin/seller-compliance/partials/{sellers-table,tabs}.blade.php`, `resources/js/admin/seller-compliance.js`.

### Complaints and Disputes (list, preview, case page)

- **Naming:** the page is "Complaints and Disputes" (matches `docs/features/admin/manage-complaints-and-disputes`). "Account report" stays as the label for the `user_report` kind of case, because the buyer and seller side and the controller use that name.
- **List (from the mockups):** heading "Manage Complaints and Disputes"; four stat cards (Total Complaints, Open Cases, In Progress, Resolved) that also filter by status; search, kind filter (all, order complaints, account reports), date and type dropdowns; table of Complaint ID, Parties (name with role beneath), Type, Status, and Date Filed; outlined type and status pills; "Waiting N days" on open cases older than two days. Search, filters, and paging refresh only the table (`casesPage` in `resources/js/admin/complaints.js`, `cs-` styles in `resources/css/admin/complaints.css`).
- **Complaint Preview popup:** clicking a row opens the centered popup from the mockup (ID, filed date, status, type, order ID, amount, description, parties, See Full Details, and Mark in progress for open order complaints). Previews are now rendered inside the swapped table. Before, new rows after a search had no modal.
- **Empty states:** "No complaints yet" (with a "Preview a sample case" button), "No cases match these filters" (with Clear filters), and per-section empty states on the case page (description, evidence, messages).
- **Sample case:** "View a sample case" shows one built in memory (`partials/sample-case.blade.php`). It writes nothing to the database. Remove the include and file once real cases exist.
- **Case page (from the mockups):** header card with a red case ID and status pill; Complaint Summary; Order Information with the existing product dialogs; Timeline (newest first); Parties Involved; Supporting Evidence with a "+N Other" tile; Messages panel. The status buttons, the review-note form for account reports (`data-draft-key` kept), and all routes and field names are unchanged. A confirmation toast shows after a status change or decision.
- **Not connected:** the Messages panel (All / Buyer / Seller / Courier) shows an empty state, and the party "Message" buttons are "Email" links (`mailto:`). Nothing links conversations to a case and the admin cannot start one, so these are not marked implemented. Requirements are in the backend needs.
- **Status and kind filters:** the controller ignores `status` and `kind`. The UI sends both; until the controller honors them, `complaints.js` only hides non-matching rows on the current page.
- **Fix during handoff:** the first popup wrote `Complaint Preview@if (...)` with no space. Blade only treats `@if` as a directive when it does not follow a word character, so it skipped the `@if` but still compiled the matching `@endif`, and the page failed with a `ParseError` ("unexpected token endif"). The directive is now on its own line. Do not glue `@if`, `@foreach`, or `@php` directly onto a preceding word; put them after whitespace or a tag.
- **Files:** `resources/views/admin/complaints/{index,show}.blade.php`, `resources/views/admin/complaints/partials/{complaints-table,complaint-row,preview-modal,sample-case,status-badge,type-badge}.blade.php`, `resources/css/admin/complaints.css`, `resources/js/admin/complaints.js`.
