### Seller Compliance
- Warnings, Violations and Suspended rows open a details popup, like the Overview rows.
- **Warning / Violation:** reason, full details, product (photo, category, price, stock, status), seller (photo, standing, score), "what this means" (score impact, how many more until the next automatic violation or suspension), and a link to the seller's record.
- **Suspended:** reason, notes, start and end, how it happened, seller standing, latest violations, and "Lift suspension" (hands over to the existing confirmation dialog).
- Compliance score is explained in the popups.
- It is `100 − 10 × violations`; warnings do not change it (backend needs, item 3a).
- **Files:** `seller-compliance/partials/{warnings-table,violations-table,suspended-sellers-table,sellers-table}.blade.php`, new `issue-detail-modal`, `suspension-detail-modal`, `score-note` partials, `resources/js/admin/seller-compliance.js` (`detailId`).

### Product Page — `buyer/products/show.blade.php`
- Variations are separate rows.
- Each variation type (for example Color, then Size) is its own row, read from the saved options of the product's variants.
- A later row only offers what is in stock for the earlier choice.
- Sold-out options are disabled, struck through, and not chosen by color alone.
- Changing the first choice keeps the later choice when it is still in stock, and clears it when it is not.
- The price shows a range until every type is chosen.
- Add to Cart stays blocked, with a message, until every type is chosen.
- A hidden `variant_id` is filled when the combination is complete, so the form posts the same fields as before.
- Variants that have no saved options fall back to the old single list.
- Add to Favorites button beside Add to Cart.
- It uses the existing Saved items store (browser storage), the same as the heart on product cards.
- Shipping fee is visible on the page, not only at checkout.
- An Order total row (`price × quantity + shipping`) is shown under Quantity.
- The fee is `$shippingFee` when the controller passes it, otherwise `0`, which is what checkout charges today.

### Shop Page — `buyer/sellers/show.blade.php`
- Products use the same grid and the same card as the dashboard.
- Up to six columns.
- "Add to Cart" opens the product page.
- The shop name is hidden on these cards because every card is from this shop (new `$showShop` option on the shared card).
- Rating and sold count are filled in from one read-only query until the controller loads them.
- Header:
  - Approved seller badge.
  - Location and joined date.
  - Copy shop link button.
  - Three-tile stats strip.
  - "Showing x–y of z" count.
  - Clear link when the in-shop search is used.

### Product Card — `buyer/partials/product-card.blade.php`
- New optional `$showShop` (default `true`).
- Nothing else changed.

### Checkout — `buyer/checkout.blade.php`
- Optional "Message for the seller" box under each shop's items.
- Posted as `seller_notes[<seller id>]`.
- Hidden until the controller passes `$sellerNotesEnabled = true`, because nothing on the server stores a note.

### Current Behavior / Specs
- **Product detail:** Variation types are shown as separate rows in the order the Seller set them, with only in-stock choices for the earlier selections. Add to Cart needs every type chosen. Add to Favorites saves the product to Saved items in this browser. The Delivery line shows the shipping fee (currently ₱0.00, because no shipping quotes exist) and an Order total row shows price × quantity plus shipping.
- **Seller shop:** Header shows an Approved seller badge, location, joined month, Chat with seller, and Copy shop link. Products appear in the same grid and card as the dashboard, with rating and sold count.
- **Gap:** Card metrics are read in the view until `SellerProfileController@show` calls `withCardMetrics()`.
- **Checkout:** The form can show an optional Message for the seller per shop (`seller_notes[seller_id]`, 300 characters) when `$sellerNotesEnabled` is true.
- **Gap:** The seller message is not stored anywhere yet.

### Backend Needs
1. **Message for the seller** — Add a nullable text column for the note on orders. In `CheckoutController@store`, validate `seller_notes` and `seller_notes.*`, save each note on that seller's order, and pass `'sellerNotesEnabled' => true` from `CheckoutController@index`. Show the note on the Seller's order detail and the Buyer's order detail. Escape it on output.

2. **Shipping fee before checkout** — There is no quote logic; `orders.shipping_fee` is always 0. Define zones and weight rules, calculate it from the Buyer's default address and the product's weight, pass `$shippingFee` to `ProductController@show`, and make checkout use the same figure.

3. **Shop page data** — In `SellerProfileController@show`, call `->withCardMetrics()` and pass the shop counts, then delete the two `TODO(backend)` blocks in the view. In-shop search and sort still need `$filters`.

4. **Favorites** — Saved items live in the browser only. A wishlist table and endpoints are needed for them to follow the Buyer across devices.

5. **Variation order** — The page reads types and options from `product_variants.options` in variant order. Loading `variationTypes.options` in `ProductController@show` would match the Seller's exact option order.
