# Progress — 5–6 October 2026 (Seller UI/UX, frontend only)

No backend, route, migration or controller changes. Nothing was built with Vite, loaded in a browser or tested; the owner verifies at desktop and narrow widths. Backend requirements are in [Seller backend needs](../features/seller/backend-needs.md).

## Products & Inventory

- **Delete product (UI only):** red "Delete product" item below a divider in each row's 3-dot menu, with an accessible confirmation dialog (focus returns to the menu button, Esc and backdrop close it), loading state, animated row removal and a toast. It sends `DELETE /seller/products/{id}`. That route does not exist yet, so the dialog states that deleting is not available on the server. Not marked implemented. Admin notification is recorded as a note only.
- **Product details modal:** new **Variations** tab (summary cards, variation types and option chips, one row per variant with image, name, options, SKU, price, stock, status and a Restock shortcut that preselects the variant; empty state for products flagged as having variations but with none stored). Details tab now shows a price range and crossed-out original price, one row per variation type instead of empty Colors/Sizes, category details, additional specifications, shipping information and the product video. Legacy single-value fields appear only when filled.
- **Fixed overlap in the Variations tab:** the first version used a six-column table that overflowed in the modal's narrow column. Replaced with a grid row list.
- Direct visits to a product's details page (for example from a notification) now have working tabs through a small `initDetailPage()` in `products.js`.

## Orders

- Redesigned the page: Live indicator, stat cards that act as filters, animated tabs with count badges, search with clear button, "Clear filters", loading bar, staggered row entry (user-initiated loads only; the 3-second poll never animates), initials avatars, optional product thumbnails, status pills with dots, action toast.
- **Empty states:** no orders, no match for filters (with Clear filters), and one for each status tab.
- **Order drawer:** status/total hero, progress track, customer card with profile link, product cards (image, variation, SKU, qty × price, line total), payment summary (shipping line only when greater than zero), history timeline, pinned action bar; slide-over sheet below 980 px.
- `index.js` rewritten in readable form with the same behavior. All ids, form field names, `data-` hooks, routes and JSON shapes are unchanged.
- **Order ID `ORD-YYYY-NNNN` is not implemented.** The live format is still `VN-` plus the padded id. Requirements are in the backend needs page.

## Dashboard (layout unchanged)

- Welcome row with time-of-day greeting, date, View orders and Add product buttons.
- Stats row is always one line (scrolls sideways below about 1180 px). Cards link to Orders, Reports, Orders › New, Orders › To Pack and Feedback; numbers count up; Total Sales shows change against the previous week.
- Sales Overview gets 6-week totals, legend toggles, peso tooltips and an empty state. Recent Orders, Top Selling Products (rank, image, sales bar), Inventory Alerts (out of stock / low stock groups with bars, product links) and Notifications (unread dot, relative time) were restyled, each with an empty state. Minimum text size raised from 7–9 px to 11.5–12 px.
- `notifications/dashboard.blade.php` is also re-rendered every 3 seconds by the seller layout poll, so it has no entrance animation.

## Regression found and fixed (6 October)

While replacing the first variation-table styles in `resources/css/seller/products.css`, a cleanup script deleted every rule between the first `.pi-vtable-wrap` (which belongs to the **Add/Edit Product form**) and the end of the appended block. This removed the Listing progress styles (`pi-progress`, `pi-bar`, `pi-steps`, `pi-dot`), the review step, form actions, form error box, upload-progress box and the form's variation editor, plus my own delete-dialog and Variations styles. The file was rebuilt from the original `products.css` (kept byte-for-byte at the top) with a clean block appended, then checked: every `pi-` class used by the products views has a rule. `seller-dashboard.css` and `order-management-orders.css` were audited for the same problem and are intact.
