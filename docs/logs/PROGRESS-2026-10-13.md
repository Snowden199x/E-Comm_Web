# PROGRESS LOG - 13 October 2026

## LOGISTICS

**Presentation only. No controller, route, model, migration, or schema change. Every page still runs on the hard-coded data in `routes/logistics_preview.php`.**

### Logistics portal UI/UX pass (Company, Province Hub, Station)
- Applied the workflow of the UI UX Pro Max skill by hand (product type, pattern, style, colour, typography, anti-patterns, pre-delivery checklist). The skill's CLI and data were not run. The result is recorded in [Logistics Portal Design System](../design/logistics-design-system.md); it keeps the existing Vendo look and adds no new brand colours.
- **Shell** (`components/logistics/shell.blade.php`): skip link, focusable `<main>`, breadcrumb, an `aria-live` toast region (any page can run `$dispatch('lg-toast', { type, message })`), the bell now opens a short list of items that link to the page where the work is done, and a "Demo data" pill beside the preview switcher.
- **Sidebar fixed (root cause):** `components/logistics/shell.blade.php` had no `x-data` on `<body>` (the admin layout has one), so Alpine never ran the sidebar bindings. Symptoms: the sidebar could not collapse or open/close, sat on top of the page (its spacer got no width), showed the full logo and the small icon at the same time, and the mobile backdrop never appeared. The body now has `x-data="{}"`. Links and the logo also close the mobile drawer, and the backdrop fades, both as in the admin sidebar. This predates the 13 October pass.
- **Bug fixed:** the portal pages marked the active tab with `aria-current` but `workspace.css` only styled `aria-pressed`, so the selected tab had no visible state. Pages now use `aria-pressed`, and the CSS also styles `aria-current="page"`.
- **Dashboards:** an "attention" list that links to the page for each task, and linked stat/flow cards (Station: Incoming, Sorting, Out for delivery, Delivered; Province: From stations, Waiting for linehaul, Arriving, Dispatched). The company dashboard shows setup problems, indents stations under their province hub, and shows load meters.
- **Rider Management:** working search and tabs with counts, empty states, approve, reject (reason of 5+ characters required), deactivate (confirmation, warns when parcels are still assigned), activate.
- **Incoming Parcels:** the rider must be chosen before "Verify & assign"; new "Not ready" action with a required reason (matches the 4 Oct pickup review rule: the parcel returns to the seller); "Mark arrived" stays disabled until the parcel has arrived.
- **Parcel Sorting / Delivery Assignments:** select-all, selected-row highlight, and a sticky bulk bar that holds the required destination (sorting) or rider (assignments). Assignments shows rider load meters with text, filters by zone, disables full riders, and blocks assigning more parcels than a rider has room for. The capacity of 16 is a demo constant, not a business rule.
- **Delivery Monitoring:** status tabs, rider filter and search all work; failed deliveries offer Retry and Return to seller.
- **Linehaul:** dispatch needs a truck rider; Receive is disabled until the truck has arrived.
- **Reports (hub and company):** meters beside numbers instead of inline-styled bars, a per-hub "above/below average" comparison, and an export button that says it is not connected.
- **Hubs / Hub Managers:** hubs are now added and edited in a validated dialog (required fields, duplicate municipality or province, valid email) and new hubs appear in the list; managers can be searched, filtered by hub, invited, deactivated with confirmation (warns when it removes a hub's only active manager), reactivated.
- **Account:** identity header showing where the account sits (company > province hub > station), inline validation, show/hide password, live password rules, confirm-password field. The 8-character, letter and number rules are demo rules; no password policy is defined yet.
- **New files:** `components/logistics/empty.blade.php` (shared empty state), `docs/design/logistics-design-system.md`. New icons in `components/logistics/icon.blade.php`: plus, edit, eye, eye-off, refresh, undo, building, bell.
- **CSS:** appended a clearly marked section to `resources/css/logistics/workspace.css` (meters, attention list, bulk bar, form helpers, tree indent, toast icon colours, small-screen table rules, reduced-motion rule for toasts). Existing rules are unchanged.

**Verification:** static only. Blade directive and HTML tag balance, Alpine `x-data` syntax (checked with `node --check`), CSS parse (PostCSS) and "every `lg-` class used is defined" were checked. No PHP was available, so the Blade was not compiled; the Vite build could not run because the uploaded `node_modules` holds binaries for another OS; no browser walkthrough was done. # Progress — 13 October 2026

## Buyer voucher visibility and notifications

- Added a checkout selector per Seller order, populated with active, unexpired shop-wide, product-scoped, or category-scoped vouchers matching selected cart lines. The page shows code, scope, minimum spend, start/end time, remaining uses and per-Buyer limit; unavailable matches show why and are disabled. Manual code entry and server quote/final validation remain available.
- On first activation, prior non-archived Buyers receive one targeted notice with the voucher code/scope and a link to the Seller shop. Unique voucher/Buyer records prevent duplicates; edits and later reactivations do not send duplicate alerts.
- Seller notification polling detects vouchers past their end date or total-use limit and creates one Seller notice linking to Vouchers. If the Seller is offline at expiry, the notice is created on their next notification poll/page load.
- Added migration `2026_10_13_120000_create_seller_voucher_notification_recipients.php` for deduplication and notification timestamps. **Owner must run `php artisan migrate`** before testing.
- The migration treats existing vouchers as previously announced and existing ended vouchers as already notified, avoiding surprise alerts for historical vouchers; the new alerts apply to later activations and expirations.
- Updated Buyer/Seller voucher and notification specs, domain pages/status, schema, future plan, and this progress log. No automated, browser, or manual tests were run per repository instructions; code review/static checks only.

## Deployment route-cache error

- Removed the redundant `/buyer/messages/fetch` route, which duplicated the `buyer.messages.fetch` name used by `/buyer/messages/{conversation}/fetch` and had no frontend caller. This resolves the duplicate-name condition reported by `php artisan route:cache`.
- The reported database connection refusal remains an environment issue: Laravel could not reach MySQL at `127.0.0.1:3306`, so migrations did not run. The deployment must point `DB_HOST` to the reachable MariaDB/MySQL host and make sure the database service, credentials, network path, and database exist.
- `public/storage` already exists; rerunning `storage:link` reports that existing link and does not explain the route or DB failures.

## Google sign-in fetch URL behind production proxy

- Changed the web Google ID-token exchange URL to a relative same-origin path. This avoids an HTTP absolute URL being generated when the app is served over HTTPS behind Cloudflare Tunnel and Laravel does not see the forwarded HTTPS scheme; such a mismatch can surface in the browser as `Failed to fetch`.
- Added safe server-side rejection diagnostics for Google token validation. Logs record only rejection categories and validation booleans, never the token, email, or claim values.
- Updated the shared Google sign-in spec. No migration or credentials change is required. Production browser verification remains with the owner after deploying the view/service changes.
