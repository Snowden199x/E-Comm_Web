# Progress — 27 September 2026

- Added public, rate-limited rider location and registration API endpoints. Registration validates PSGC city/province, personal/vehicle fields, and three image uploads; it creates a pending courier linked to the uniquely matched approved active logistics center. Verification images are stored on the private local disk.
- Extracted the existing order city/province matching rule into `LogisticsCenterMatcher` so order routing and rider registration use the same policy. No new migration was added.
- Connected the separate E-Comm_Mobile `vendo_rider` client to registration, approved login, assigned parcels, the three supported camera scans, and logout. Added mobile-specific docs and working rules in that repository.
- Reviewer download of private rider documents, email verification, SOC5/SOC6 scans, delivery completion/proof, and broad offline reconciliation remain open. The owner performs testing; no automated tests or app walkthroughs were run by the agent.
- Added a bundled barangay snapshot and a city-scoped rider API endpoint. Registration now accepts a barangay code and stores the canonical name only after validating that it belongs to the selected city. This fixes free-text barangay mismatch without a database migration. The separate Flutter rider client now loads barangays from the web API and uses localhost by default for Linux debug builds; the configured production URL remains the release default. The owner will verify the flow; no tests or app walkthroughs were run by the agent.
- Extended approved rider scans for cross-hub orders with ordered SOC5, SOC6, and destination-leg milestones after origin sorting. The scan API and assigned-work list, order statuses/notifications, buyer timeline, and logistics dispatch pages now reflect these stages. Removed the manual direct-send action so new cross-hub parcels follow the scan sequence; legacy in-transit parcels remain receivable. Clarified empty incoming parcels and no-approved-rider guidance. No migration was added because status and scan-type columns are strings. The origin pickup rider handles all inter-hub scans in this first version; linehaul rider handoff, physical SOC custody, and delivery completion remain gaps. Owner testing is pending.
- Added an assigned destination-rider `delivered` scan after `out_for_delivery` using the existing row lock, idempotent scan/status events, `delivered_at`, and seller/buyer/center notifications. Buyer receipt confirmation remains separate; the buyer's final progress step now says Rate Product and links to the existing review section after confirmation. New and stored seller shipment-update notifications now open the full owned Orders view, and direct browser visits to shipment/completed-order drawer endpoints redirect there too. Updated the affected feature and status docs. No migration or dependency was needed. Independent delivery proof and exception handling remain open; owner testing is pending.
