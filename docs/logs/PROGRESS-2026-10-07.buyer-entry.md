# Progress — 7 October 2026 (Buyer: home, orders, account and settings)

Views, CSS, and Blade partials only. **No controller, route, model, service, or migration was changed**, and nothing was run or tested in a browser. Owner verification is pending. What the backend still has to do is listed below.

## What changed

- **Dashboard:** the announcement banner is now a carousel (arrows, swipe, keyboard arrows, dots that double as the 6.5s autoplay timer, pause on hover/focus/hidden tab). New quick-link cards (Track my orders, Saved items), a benefits strip (Cash on Delivery, order tracking, approved sellers, chat), "Shop by category", a "Saved for later" row (only when the buyer has saved items), a clearer Recommended-for-you header with "View all products" and "See more products", and the footer. Sections fade up as they scroll in.
- **Product card:** now a preview-style card. The whole card opens the product page. Heart button (saved items), discount badge when `compare_at_price` is supplied, "Sold out" overlay, rating and sold count, shop name with a store icon, and a light outlined **Add to Cart** button (opens the product page on the dashboard, `$toProduct`). All existing branches (compact, variations, colour/size quick add, direct add) and form fields are unchanged.
- **Saved items (favorites):** heart on cards, a heart button in the header with a count, a slide-over panel, a "Saved for later" row on the dashboard, and a Saved items section in Settings. **Stored in the browser only** (localStorage, per user id); saving never touches the cart.
- **My Orders:** removed `returned` (tab label is now **Cancelled**; the returned badge was removed). Cancelled orders show **Cancelled by you / Cancelled by the seller** and the reason, read from the status event note written by `OrderCancellationService` ("Buyer/Seller cancellation reason: ...").
- **Account Management and Settings** (one page, `buyer/account.blade.php`): side menu with two groups. Account: Profile (banner, picture, profile form, read-only registered address), Password and security. Settings: Appearance and motion (text size, reduce animations), Notifications (sound), Saved items, Privacy and policies (Terms, Privacy Policy, and the admin-published policies dialog). Deep links: `?tab=profile|security|settings|preferences|notifications|saved|privacy`. The account menu now has **Saved items** and **Settings**. Field names and routes of every form are unchanged. The ✓ character in the password success message was removed (no emojis rule).
- **Settings are stored on the device** (localStorage, per user id), not on the account.
- **Page animations on every load:** the header drops in and each block of the page (and each product card) fades up in sequence, then more blocks animate in as you scroll. Pages that do not mark their own sections are animated automatically by the layout script. A thin gold progress bar runs when a link is clicked or a form is submitted. All of it respects Settings > Reduce animations and the device's reduce-motion setting. (A full-screen loading screen was built first and removed at the owner's request.)
- **Footer:** `buyer/partials/storefront-footer.blade.php`, included by the buyer layout (pass `:footer="false"` to hide on a page). Links only to pages that exist today.
- **Messages page:** restyled from the old gray/emoji look to the Vendo design. Two columns: seller chats (avatar, name, last message, order tag, time, unread count) and Vendo Support. Support start screen is three topic cards (General Inquiry, Raise a Concern, Other; same `reason` values). The open support chat has a header with status, plum/white bubbles, an empty "Say hello" state, SVG paperclip and send icons (emoji removed), and a larger image viewer. The polling and chat scripts are unchanged. The seller chat thread is covered in the next item.
- **Seller chat page** (`buyer/marketplace-chat.blade.php`): restyled as a **buyer-only skin**. The thread markup and script are shared with the Seller side (`shared/marketplace-thread.blade.php`, `css/shared/marketplace-chat.css`) and were **not changed**; the wrapper now has the classes `mc-page--buyer vb-reveal` and the new rules are scoped to `.mc-page--buyer` at the end of `css/buyer/layout.css`. Plum/white bubbles, system messages as soft gold, order cards, an icon on the empty state, restyled share-an-order and composer (styled file button), focus states, mobile layout, message entrance animation. Needs no Vite change.
- **Report modal** (Report this seller): restyled for buyers only. `shared/user-report-modal.blade.php` and `css/shared/user-report.css` are shared with the Seller side and were **not changed**; the new rules are scoped to `.mc-page--buyer` at the end of `css/buyer/layout.css`, and a small script in `buyer/marketplace-chat.blade.php` adds a hint under the reason, a character counter, chips for the chosen evidence files, and "Sending..." on the button. The report is still submitted by the shared script (same fields: `context`, `reason`, `description`, `evidence[]`). Sticky action bar, dashed evidence picker, entrance animation, and a toast-style confirmation.
- **Notifications page:** whole message area opens the notification, unread accent bar, "N new" badge, per-row mark-as-read tick, type filter chips for the current page (Orders, Messages, Reviews, Announcements, Alerts), day group counts, link to the sound setting, entrance animation. New partial `buyer/notifications/partials/icon.blade.php` shared with the header dropdown (`recent.blade.php`), which now shows type icons, an unread bar and a clearer empty state.
- **Header bell:** the unread badge now has the same size and shape as the heart and cart badges.
- **Header:** the cart icon sat too high because `#cart-badge` was a second grid row inside the cart link; it is now `display: contents`. Header icons are all 22px. Added a back-to-top button.

## Backend needs (nothing done yet)

The full, prioritized list with details is consolidated in [the 7 October frontend pull review](../design/2026-10-07-pulled-frontend-review.md). Summary:

1. **Wishlist (saved items on the server).** Table `wishlist_items` (`user_id`, `product_id`, unique together, timestamps), toggle/list/remove endpoints under the buyer group, and a server-rendered Saved items list. Today it is browser-only, so it does not follow the buyer to another device and can be cleared by the browser. A saved product that is later deleted or out of stock cannot be flagged either.
2. **Settings page route (optional).** A dedicated `GET /buyer/settings` (`buyer.settings`) and controller method, so Settings and Account Management are separate URLs. The view already holds both groups and can be split.
3. **Saved settings per account.** A `user_settings` table (or JSON column) for text size, reduced motion, notification sound, plus notification choices per type (order updates, messages) and email notifications. Today only the device-level ones exist.
4. **Cancelled-by data.** Add `cancelled_by` and `cancel_reason` columns to `orders` (or eager load `statusEvents` in `OrderController@index`). The page currently reads the status event note and lazily loads it per cancelled order.
5. **Product data for the card:** `reviews_avg_rating`, `sold_count` and `compare_at_price` (already optional in the card). Needed for the rating, sold count and discount badge to appear.
6. **Dashboard:** pass announcements as `$announcements` (published, newest first, a few). Optional: `image` per announcement to use as slide art.
7. **Account page:** none required. Optional: `email_verified_at` and order counts for a richer header.
8. **Messages:** eager load `seller.sellerDetail:id,user_id,business_name` in `MessageController@sellerConversations` if the list should show shop names instead of account names. Optional: per-message timestamps in the support chat JSON (`created_at`) to show times on bubbles; an unread count for Vendo Support.
9. **Still open from 6 October:** the server lets a Buyer cancel at `preparing` and `ready_for_pickup`; only the page hides the button. `buyer/orders/show.blade.php` still lists `returned` in its terminal-state checks (harmless, not changed).
