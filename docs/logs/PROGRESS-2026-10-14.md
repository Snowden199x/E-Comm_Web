## Province Logistics implementation

- Added two additive migrations: unique Logistics province coverage plus real Main Hub/station facilities, then ordered parcel facility stops and idempotent scan events. Unique-province legacy centers receive claims and Main Hubs during backfill; duplicate-province legacy accounts remain unclaimed for Admin review. No old SH/SOC routes or scan rows are deleted.
- Logistics registration now selects unclaimed province coverage and validates the Main Hub address against PSGC; Admin review displays that coverage, blocks approval without a unique claim, and releases a pending claim on rejection. Ready-order and Rider registration matching now resolve the approved active account by province claim.
- Added protected Hubs & Stations navigation, clickable facility cards and details, station create/edit/availability actions, and a Vendo-style scan modal. ZXing reads the Seller label's QR and Code 128 tracking number from the browser camera; manual entry handles unavailable cameras. The server checks facility ownership, active state, expected stop sequence, and a unique retry key.
- New sorting writes explicit ordered station stops, placing the destination Main Hub before any farther destination-province station. Facility scans record origin Main Hub departure and ordered arrival/sort/departure at route stops, order status history and scoped Seller/Buyer/Logistics notifications. The first stop requires origin departure; cross-province origin departure requires a Truck Rider assignment. New routes require final-facility sorting before local Rider assignment. Truck assignments expose new stops read-only; the Rider API rejects legacy SOC scans on these orders and includes a station dispatch address for delivery assignments.
- Added the previously missing live `logistics.dispatch.index` Blade view so incoming/sorting/delivery routes have a protected operational page. Existing public `/logistics-preview/*` screens remain examples.

Made the X close button visually clear. Barcode/QR reads now post automatically; each route-stop scan records arrival and sorting together, with no confirmation button or action dropdown.
