# Progress — 15 November 2026

## Role-specific login isolation

- Buyer login now posts to the Buyer endpoint; the root `/login` handler is Buyer-only instead of accepting Seller and Logistics accounts and redirecting them to their dashboards.
- Buyer and Seller password credential lookups now include their expected role. Admin login lookup includes `role=admin` through the separate `admin` guard. Logistics login retains its allowlist for Logistics-side roles and rejects Buyer/Seller/Admin accounts.
- Existing route middleware continues to enforce Buyer, Seller, Logistics Company/Hub and Admin role access after login. Google login already rejects a saved account whose role differs from the selected login role.
- No schema change. Owner browser verification remains pending; automated tests were not run.

- Kept the compact app link in the Buyer hero and the separate Rider app button/QR on the Logistics landing page.

## Limits ownership and Delivery Fees page

- Moved the extra delivery attempt action from Admin Limits & Overrides to the destination Station Hub Delivery Queue. The Station-scoped endpoint checks parcel ownership/status, limits grants to three, locks the order, stores the reason and actor in the order timeline/override fields, and notifies the Buyer and assigned Rider. Rider cutoff/rescheduling continues to use the saved extra-attempt total.
- Admin Limits & Overrides now handles return-window extensions only. Updated the Admin and Logistics feature specs, domain status and docs index.
- Fixed the Delivery Fees history query to select the persisted `orders.order_number` and `tracking_number` columns instead of the non-column `orders.number` accessor, with a legacy display fallback.
- No migration added. Owner browser verification remains pending; automated tests were not run.
