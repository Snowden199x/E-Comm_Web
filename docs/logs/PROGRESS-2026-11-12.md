## Logistics: Station Hub parcel operations restyle (Pickup requests, Task assignment, Delivery queue, Incoming, Sorting, Outgoing)

**What changed:** One view, `logistics/station/operations.blade.php`, renders six Station Hub pages through `StationOperationsController::index` (route default `mode`): `lgp.station.pickups`, `.tasks`, `.delivery-queue`, `.incoming`, `.sorting` and `.outgoing`. All six now use the Seller pastel lilac system, the same `.lgh` layer as the Province Hub pages. Routes, guards, which parcels appear and the assign and decline rules are unchanged. The older views `station/pickups`, `tasks`, `delivery-queue`, `incoming`, `sorting` and `outgoing` are not used by these routes and were not changed.

- **Page.** Header with the station name and a one-line description of the page; **Assign driver** on Outgoing (primary) and on the Delivery queue (soft). Status chips with counts on Pickup requests (Needs a rider, Rider assigned, Picked up), Delivery queue (Ready to assign, Assigned, Out for delivery, Failed), Task assignment (Assigned, In progress, Failed, Expired) and Incoming (Awaiting scan, Received). Search runs as you type on tracking number, name, address, rider or next stop, across the rows loaded (at most 200, as before). The dashboard links `?tab=failed` and `?tab=out` now work: the Delivery queue opens on that chip.
- **Table.** Five columns, not six: the seller or buyer sits under the tracking number, and the old Seller and Address columns are now one Parcel column and one address column. The status pill follows the shared mapping; a rider cell shows Rider assigned, Needs a rider or Not ready. One click on a row does the main action (assign a rider) or opens Parcel tracking for that parcel. Every row has a visible button: **Verify and assign** (Pickup requests) or **Assign rider** (Delivery queue), **Reassign rider** when one is set, **Return to seller** for an unverified pickup, otherwise **Track parcel**.
- **Dialogs.** Assign rider and Return to seller use the blurred backdrop, the rotating close button and a phone bottom sheet. The rider and the reason are checked in the browser first. The old inline "Return to seller" reason field on each row is now a dialog.
- **Rows.** The controller now sends each row's raw status as `key`, which the chips and pill colors use. Nothing else about the rows changed.
- **States.** One empty state per page, each with a button; a "nothing in this status" state; and "no parcels match your search" with **Clear filters**. A notice with a link to Riders shows when there are parcels to assign but no available rider (the assign buttons are disabled then). Loading is the shell skeleton plus a spinner on the pressed button. Messages use the top banner.
- **Trips table (Outgoing).** Same trips, now with a status pill and the driver and vehicle in one column.
- **Styles.** Reuses `hubs-theme.css` and `drivers-theme.css`; new `resources/css/logistics/operations-theme.css`. Registered in `vite.config.js`.
- **Controller (`StationOperationsController`).** Wording only, plus the `key` above: validation messages and the conflict errors in `assign` and `declinePickup`, and success messages that name the parcel and the rider. The not-sorted, rider-unavailable and already-started errors now say what to do next.

**Known gaps:** The list shows at most 200 parcels (the controller limit). Scanning arriving parcels is done with the camera button in the page header, not on this page. There is no per-parcel page, so **Track parcel** opens Parcel tracking filtered to that parcel.

**Not verified:** no PHP or browser run in this session, so the Blade view and the controller changes are untested. Run `npm run build`, then check all six pages at a station with data and one with none, assigning a pickup and a delivery (with a rider chosen and not chosen), Return to seller (a short and a valid reason), a station with no active rider, the chips, search, `?tab=failed` on the Delivery queue, and the phone layout.

## Logistics: Station Hub Riders restyle

**What changed:** The Station Hub Riders page (`GET /logistics/portal/station/riders`, route `lgp.station.riders`) now uses the Seller pastel lilac system, the same `.lgh` layer as the Province Hub pages. Routes, guards, data and the review and status rules are unchanged. The page was unstyled before.

- **View.** `resources/views/logistics/hub/riders.blade.php` rewritten around the same Alpine logic. Status chips with counts (Active, Applications, Rejected, Inactive) replace the tabs; the page opens on Applications when any are waiting, or on the tab in `?tab=`. Search runs as you type (name, email, vehicle, area). Every row has a visible action: **Approve rider** and **Reject application** for an application, **Deactivate rider** for an active rider, **Activate rider** for an inactive one, and a Rejected pill for a rejected one. The header has an **Assign tasks** button.
- **Dialogs.** The reject (reason required, 5+ characters) and deactivate confirm use the blurred backdrop, the rotating close button and a phone bottom sheet. Deactivate is blocked with a link to Task assignment while the rider has open parcels, instead of failing on the server.
- **Styles.** Reuses `hubs-theme.css` and `drivers-theme.css`; new `resources/css/logistics/riders-theme.css` adds the avatar and the person cell. Registered in `vite.config.js`.
- **Status colors.** Active = mint, Applications = butter, Rejected = rose, Inactive = lilac.
- **States.** Empty states for no riders at all, for each status (each with a button), and "no riders match your search" with **Clear filters**. A spinner shows on the pressed button. Errors show under the reason field, inside the dialog, or in the top banner, including offline, expired session and server errors.
- **Removed.** The Valid ID, Licence and OR/CR links on each application pointed to `#` and opened nothing; they are gone. The Station Hub has no route to view a rider's documents.
- **Controller (`PortalController`).** Wording only, in `reviewRider` and `updateRiderStatus`: validation messages, the already-reviewed, open-parcels and not-approved errors, and a `message` in each JSON reply that names the rider and the result. The reply fields the page used before are unchanged.

**Known gaps:** Applications cannot be checked against the uploaded documents from this page, because there is no station route for rider documents. A rejected application cannot be reviewed again; the server only reviews pending ones. There is no per-rider page, so there is nothing to open on a row click.

**Not verified:** no PHP or browser run in this session, so the Blade view and the controller changes are untested. Run `npm run build`, then check approve, reject (short and valid reason), deactivate (with and without open parcels), activate, search, the chips, `?tab=applications`, a station with no riders and the phone layout.

## Logistics: Station Hub Drivers restyle

**What changed:** The Station Hub Drivers page (`GET /logistics/portal/station/drivers`, route `lgp.station.drivers`) now uses the Seller pastel lilac system, the same `.lgh` layer as Province Hub > Transport Drivers. Routes, guards, data and the approve, reject, activate and deactivate rules are unchanged. The page was unstyled before.

- **View.** `resources/views/logistics/station/drivers.blade.php` rewritten around the same Alpine logic. Status chips with counts (Applications, Waiting for Province Hub, Active, On trip, Inactive) replace the tabs; the page opens on Applications when any need this hub's decision. Search runs as you type. One click on a row opens the driver. Every row has a visible button: **Review application** when this hub decides, **Assign trip** for a driver who can take one (opens Driver assignments with the driver chosen), and **View details**. The header has an **Assign driver** button.
- **Dialogs.** Driver details and the reject or deactivate confirm use the blurred backdrop, the rotating close button and a phone bottom sheet. Buttons read **Approve driver**, **Reject application**, **Activate driver**, **Deactivate driver**, **Assign trip**. Documents open in a new tab.
- **Styles.** Reuses `hubs-theme.css` and `drivers-theme.css`; no new stylesheet and no new `vite.config.js` entry.
- **Status colors.** Available = mint, On trip = sky, Off duty and Inactive = lilac, Needs review and waiting for the Province Hub = butter, Rejected and expired licence = rose, licence due within 60 days = butter.
- **States.** Empty states for no drivers at all and for each status (each with a button), and "no drivers match your search" with **Clear filters**. A spinner shows on the pressed button. Errors show under the reason field, inside the deactivate dialog, or in the top banner, including offline, expired session and server errors.
- **Fixes.** Drivers on a trip were in no tab, so they disappeared from the page while on a trip; they now have an On trip chip. A server error while deactivating was hidden, and deactivating a driver on a trip did nothing without a message; both now show a message.
- **Controller (`PortalController`).** Wording only, in `reviewStationDriver` and `updateStationDriverStatus`: validation messages, the already-reviewed, expired-licence, Province-Hub-only and on-trip errors, and success messages that name the driver and the result. The Province Hub methods keep the wording from the drivers restyle.

**Known gaps:** There is no per-driver page, so the details open in a dialog. Approval needs an unexpired licence; the page cannot ask the driver for a renewed one.

**Not verified:** no PHP or browser run in this session, so the Blade view and the controller changes are untested. Run `npm run build`, then check approve, reject (short and valid reason), deactivate, activate, a driver with an expired licence, a Province Hub application (read-only), a driver on a trip, **Assign trip**, search, the chips and the phone layout.

## Logistics: Station Hub Driver assignments restyle

**What changed:** The Station Hub Driver assignments page (`GET /logistics/portal/station/trips`, route `lgp.station.trips`) now uses the Seller pastel lilac system, the same `.lgh` layer as Province Hub > Transport Trips. Routes, guards, data and the assign, cancel, depart and arrive rules are unchanged.

- **View.** `resources/views/logistics/station/trips.blade.php` rewritten around the same Alpine logic. The four summary tiles are gone (the chip counts say the same). Status chips with counts (All, Scheduled, In transit, Completed, Cancelled) replace the tabs; search runs as you type. One click on a row opens the trip. The table has seven columns instead of eight: the trip shows whether it is sent from this station or arriving here, and driver and vehicle share a column. Each row has a visible primary button: **Record departure** for a scheduled trip that leaves here, **Record arrival** for a trip in transit that arrives here, otherwise **View details**. **Cancel trip** is in the details dialog.
- **Assign driver.** The dialog keeps the same fields (hub, driver, vehicle, departure, expected arrival, parcels) with the blurred backdrop, the rotating close button and a phone bottom sheet. Parcels are rows with a checkbox; **Delivers in this hub** is mint and **Passes through** is lilac. A search appears above eight parcels. An action bar stays in view with the parcel count, **Cancel** and the primary **Assign driver**, which shows a spinner while saving. The browser checks each field first (past departure, arrival before departure, licence ending before departure, no parcel selected) and shows the message under the field; server messages map to the same fields.
- **Blockers.** When there is no other active hub, no free driver or no free vehicle, a rose notice at the top says which one and how to fix it (with a link to Drivers), and **Assign driver** is disabled. After a save, the driver, vehicle and loaded parcels leave the lists, so they can't be picked twice. A hint in the dialog asks for a reload after a trip is cancelled or received, so the freed driver and vehicle show again.
- **Assign trip from Drivers.** `?driver=` still opens the form with that driver chosen. If that driver can't take a trip, a banner says so instead of an empty select.
- **Details dialog.** Callouts that follow the status and whether this station sends or receives the trip, facts, a manifest whose parcels open Parcel tracking for that parcel, and progress steps.
- **Status colors.** Scheduled = butter, In transit = sky, Completed = mint, Cancelled = rose.
- **States.** Empty states for no trips at all, nothing in a status, and "no trips match your search" with **Clear filters**. A spinner shows on the pressed button. Errors show under the field, inside the dialog, or in the top banner, including offline, expired session and server errors.
- **Styles.** Reuses `hubs-theme.css`, `drivers-theme.css` and `trips-theme.css`; new `resources/css/logistics/station-trips-theme.css` (assign dialog, parcel list, action bar, blocker notice). Registered in `vite.config.js`.
- **Controller (`PortalController`).** Wording only, in `storeStationTrip`: validation messages, the past-departure, driver, vehicle and parcel errors, and the success message. A driver, vehicle or parcel that is no longer valid used to return a bare "No query results" 404; it now returns a clear message. `stationTrips` also passes `trackingUrl` and `driversUrl`. The depart, arrive and cancel messages keep the wording from the Province Hub Trips restyle.

**Known gaps:** There is no per-trip page, so the details open in a dialog. Scanning parcels for departure and arrival happens in the facility scanner, not on this page. Vehicles belong to the Province Hub, so a station with no free vehicle can only ask the Province Hub; there is no link for that.

**Not verified:** no PHP or browser run in this session, so the Blade view and the controller changes are untested. I checked that the page script parses and the Blade tags balance. Run `npm run build`, then check assigning a driver to a Province Hub and to another station, a past departure, an arrival before the departure, a driver whose licence ends before the departure, no parcels selected, Record departure and Record arrival, cancel with a short and a valid reason, a station with no free driver or vehicle, `?driver=` from the Drivers page, search, the chips and the phone layout.

## Logistics: Station Hub Cash discrepancies restyle

**What changed:** The Station Hub Cash discrepancies page (`GET /logistics/portal/station/cash/discrepancies`, route `lgp.station.cash.discrepancies`) now uses the Seller pastel lilac system, the same `.lgc` layer as Station Hub > Cash collections. Resolving works as before: a note of at least 5 characters turns the receipt to Resolved and releases its cash to be sent to the Province Hub.

- **View.** `resources/views/logistics/station/cash-discrepancies.blade.php` rewritten. Three tiles (open discrepancies, open difference, resolved), status chips with counts (All, Open, Resolved), a search by receipt reference or rider that runs on Enter, and a six-column table: the "expected", "received" and "difference" columns became Expected and Received with the difference under it (rose when short, butter when over). One click on a row opens it; every row has a visible button, **Resolve** for an open one and **View details** for a resolved one. A **Open cash collections** button sits in the header.
- **Resolve dialog.** Replaces the inline form on each row. It shows the amounts, the difference, the receipt note and the parcels, and asks for a resolution note (checked in the browser first). A resolved receipt shows how it was settled and by whom. After a server error the dialog reopens with what was typed.
- **Styles.** Reuses `cash-theme.css`; new `resources/css/logistics/station-discrepancies-theme.css` adds the three-tile row, the difference colors and the parcel chips, registered in `vite.config.js`.
- **Status colors.** Discrepancy = rose, Resolved = mint.
- **States.** No discrepancies at all, no open ones (mint), nothing resolved yet, and "no discrepancies match your filters" with **Clear filters**. Spinner on the submit button; errors in the top banner and under the note field.
- **Controller (`StationCashController`).** `discrepancies` now takes optional `?status=` and `?q=` filters and passes the status counts and the open difference, because the list is paged at 20; the old list and order are otherwise the same. A search over 100 characters goes back with a message. `resolve`: wording only, plus the "already resolved" case is now a validation message instead of a bare 409 page.

**Not verified:** no PHP or browser run in this session. Run `npm run build`, then check Resolve with a short note and a valid one, a resolved receipt, each chip, a search by reference and by rider name, paging with a filter, a station with none, and the phone layout.
