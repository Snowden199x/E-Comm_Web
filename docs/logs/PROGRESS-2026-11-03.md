# Progress log: 3 November 2026

## Admin UI/UX pass: Platform settings

- **Page.** Rebuilt `admin/platform-settings/index.blade.php` on the Admin design system. Heading with one primary action ("Create announcement"), shared flash banner, four stat cards that filter the list (the status dropdown is gone), shared search and date toolbar, bordered table with `tint` header, status chips (success = published, warning = scheduled, neutral = draft), and a neutral audience chip.
- **Dialogs.** The seven per-row modals (view, edit and delete for announcements, view, edit and delete for policies, plus create) are replaced by `partials/announcement-dialog.blade.php` (one shared dialog: create, edit, delete confirm) and `partials/policy-dialog.blade.php` (one editor per policy with delete confirm). The "View" buttons are gone; "Edit" opens the editor directly.
- **Bug fix.** Rows loaded by search, filter or paging had no modal, so "View" did nothing for them. Rows now carry their own data into the shared dialog.
- **Bug fix.** An announcement saved as Draft or Published could keep a leftover schedule date, because the hidden date field was still submitted. The date is now stored only while the status is Scheduled.
- **Policies.** All four types are listed. A missing type shows "Not added" and an "Add" button; adding opens the editor. An empty policy is flagged ("Empty. Users can't see it."). The editor says who is notified on save. The rich-text editor starts the first time the dialog opens, and a plain textarea takes over if the editor script fails to load. Policies are no longer paginated (there are at most four).
- **Chat greeting.** Counter, error under the field, "Save greeting" disabled until the text changes.
- **States.** Empty (no announcements, no matches with "Clear filters"), loading (progress bar and dimmed list while the list refreshes, button spinner on every submit), error (banner with "Try again" when the list cannot refresh).
- **Errors say the fix.** Client checks run first, with the fix under the field. Server validation messages are rewritten the same way. After a failed save the dialog reopens with the typed values.
- **Controller.** `PlatformSettingsController` rewritten: values validated against the allowed lists, message limit of 2,000 characters, future date required for scheduled announcements, search escapes `%` and `_`, date filter matches the date shown in the table, counts come from one grouped query, a delete that empties the last page steps back one page, success messages use `session('success')` (the old `confirmation` keys had no UI). Policy notification text changed from "Policy Updated / Please review the changes." to "Policy updated / ... Review what changed."
- **Shared files.** `admin/partials/filter-toolbar` gained `$noDropdown`; `x-admin.icon` gained `plus` and `trash`.
- **Docs.** `docs/design/admin-design-system.md` (two rules), `docs/features/admin/content-customization/spec.md`.
- No migration.

**Verified:** Alpine `x-data` blocks parse with `node --check`; tag balance on every changed Blade file; every `vd-*` colour class and shared CSS class used exists. **Not verified:** no PHP here (`php -l` not run), no browser walkthrough, no `npm run build`. Run the build, then check create, edit, delete, a scheduled announcement, a policy add and edit, and the greeting at phone, tablet and desktop widths.

**Known gaps**

- The policy icons in `public/assets/icons/platform_settings/` and the stat card icons there are no longer used by this page. They are left in place.
- The loading skeleton for this page is still the shared "form" shape (`admin.platform-settings.*` in the layout map); it is close but not an exact match.
- Scheduled announcements go live by time comparison on read (Buyer dashboard); nothing changes the stored status from "scheduled" to "published" when the time passes, so the chip keeps saying "Scheduled".
- Policy updates still notify every matching user on each save, one insert per user.
- The sidebar label is still "Platform Settings" (title case) like the other sidebar labels.
