# Admin Delivery Fees and Cash Remittances

**Status:** Web workflow written in code; migrations and owner verification pending. Part of the [COD cash and delivery fee design](../../../design/cod-cash-and-delivery-fee-distribution.md).

**Delivery Fees** (`GET admin/delivery-fees`, `PUT admin/delivery-fees`, `admin.delivery-fees.*`, Business group in the Admin sidebar) edits the single `delivery_fee_settings` row: the **delivery fee commission %** (Vendo's share of the delivery fee after the Rider's fixed pay) and the **seller commission %** (Vendo's share of the item price). Both are 0 to 100 with two decimals. Only a super admin can save; other Admins see the values read-only. The row records `updated_by`, and the page shows who last changed it and when. A live preview applies the typed rates to a ₱100 fee with ₱10 Rider pay and to a ₱500 item. Each order saves the rates in force when it is placed, so changes apply to new orders only. No admin action log entry is written because `admin_action_logs` requires a target user.

The same page shows delivery commission earned (all time and this month), the number of parcels split, and a paginated table of distributions: one row per delivered parcel whose order carries saved rates, with delivery fee, Rider, Vendo, Logistics, the rates used, settlement date and a "Needs review" tag for route mismatches. Orders from before saved rates existed use the earlier per-stop rule and are not listed.

**Cash Remittances** (`GET admin/cash-remittances`, `POST .../{remittance}/receive`, `PATCH .../{remittance}/resolve`, `admin.remittances.*`) lists `company_to_vendo` batches sent by Logistics Companies, pending first, with Company, parcels, expected and received amounts and status. Confirming a batch takes the amount received. A match sets the batch `received` and credits its orders to the Seller automatically (`credited_to_seller`); a difference requires a note and holds the orders in `discrepancy` until an Admin resolves it with a note, after which they are credited. The shared `CashRemittanceService` performs both steps under row locks and a batch can be confirmed only once. Admin accounts are `users` rows (guard `admin`), so the confirmer is stored in `verified_by` and `resolved_by`. Nothing here moves real money.

The existing Admin Commission and Reports pages now calculate commission per order from each order's saved seller rate (the fixed 10% for older orders), so a rate change never alters past commissions; `CommissionSetting::currentRate()` returns the current setting and is used for display only. The Seller side is the [Seller earnings spec](../../seller/earnings/spec.md).
