# Shipping location snapshot

`psgc-locations.json` contains province and city/municipality names and codes fetched on 26 September 2026 from the PSGC API mirror used by the existing registration form: https://psgc.gitlab.io/api/. The authoritative classification is the Philippine Statistics Authority's PSGC: https://psa.gov.ph/classifications-api/psgc. The snapshot adds Metro Manila (`130000000`) as a selectable top-level area because the mirror's provinces list omits NCR. Two independent cities without a province association in the mirror are omitted. This is a fixed operational reference and must be reviewed when PSGC boundaries change.

`psgc-barangays.json` contains barangay codes and names grouped by the 1,632 cities/municipalities in `psgc-locations.json`. It was derived on 27 September 2026 from the mirror's `/api/barangays/` endpoint. The source returned 42,046 records; 41,964 belong to cities/municipalities in the current bundled catalog. The other 82 belong to the two independent cities omitted above. The mirror reported a 2022 last-modified date, so this snapshot must be refreshed and compared with the latest official PSGC before treating it as current administrative data. Rider registration uses this local snapshot at runtime; it does not call the mirror during submission.

`municipality-coordinates.json` adds approximate municipality points from the 2025 GeoNames Philippines postal-code dump, joined to PSA Q4 2024 PSGC codes by the open-source `ph-geo` project. The project code is MIT licensed; its coordinate data is GeoNames CC BY 4.0. Attribution: GeoNames, https://www.geonames.org/; dataset and methodology: https://github.com/kon2raya24/ph-geo. These are representative postal-point averages, not official PSA centroids, facility coordinates, road distances, or service coverage. Vendo uses them only to rank approved logistics-center municipalities within the same province; missing or tied points remain unresolved. Refresh and code-match coverage against the current PSGC snapshot before relying on nationwide routing.

The server validates buyer checkout city/province combinations against this snapshot. Seller, buyer, and logistics-center municipality names are resolved through PSGC codes before approximate distance ranking. The location catalog remains a fixed reference and does not infer transport routes, facility coverage, or delivery time.
